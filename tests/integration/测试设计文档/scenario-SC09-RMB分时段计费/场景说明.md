# SC09 RMB 分时段计费

## 1. 场景背景与目的

BFE v0.5 在 `AIConf.ModelTable` 中引入 `Tiers` / `TierPrices` 支持，允许按请求发生时刻匹配不同价格 tier（如 `peak` / `off_peak`），并区分工作日与休息日。

本场景验证：

- 配置 `Tiers` 后，请求在活跃 tier 时段内命中，按 `TierPrices` 扣减 RMB 配额。
- 未配置 `Tiers` 时退化到默认 `Prices` 计费，保持向后兼容。
- 在 `peak` tier 下正确区分缓存命中 / 未命中 token，分别使用对应价格。
- 对非流式和 SSE 流式响应均正确计费。

> 说明：为解决 `ActiveTierName` 使用 `time.Now()` 导致的测试时间不确定性，本场景将 `peak` tier 配置为覆盖全周全天（`00:00-23:59`，weekdays `[0,1,2,3,4,5,6]`），保证任意时刻运行测试都会命中 `peak`。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程与嵌入式 Redis（`github.com/alicebob/miniredis/v2`）。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | 启用 `EnableAiGateway`，加载 `mod_ai_route`、`mod_ai_token_auth`、`mod_body_process` |
| `mod_ai_route/mod_ai_route.conf` | 指定 `ai_route.data` 路径 |

## 4. Cluster 与 AIConf 设计

### 4.1 测试 cluster

| cluster | 用途 |
|---------|------|
| `cluster_rmb` | 配置 `Tiers` + `TierPrices`，用于验证 tier 价格命中 |
| `cluster_no_table` | 只配置默认 `Prices`，无 `Tiers`，用于验证 fallback 到默认价格 |

> 为复用 SC03 已有的 cluster/sub 名称映射，避免改动公共 helper，本场景中的集群仍命名为 `cluster_rmb` 与 `cluster_no_table`，但其语义分别对应“配置了 tier”与“未配置 tier”。

### 4.2 `cluster_rmb` 的 `AIConf`

```json
{
    "AIConf": {
        "Type": 0,
        "Provider": "mock-provider",
        "Keys": [
            {
                "Name": "key-primary",
                "Key": "sk-primary",
                "Weight": 100
            }
        ],
        "KeyPolicy": {
            "Strategy": "weighted_random",
            "MaxRetries": 0
        },
        "ModelTable": {
            "Currency": "RMB",
            "TimeZone": "Asia/Shanghai",
            "Tiers": [
                {
                    "Name": "peak",
                    "TimeRanges": [
                        {
                            "Weekdays": [0, 1, 2, 3, 4, 5, 6],
                            "Start": "00:00",
                            "End": "23:59"
                        }
                    ]
                }
            ],
            "Models": [
                {
                    "Provider": "mock-provider",
                    "Model": "deepseek-chat",
                    "BaseModel": "deepseek-chat",
                    "Mode": "chat",
                    "Capabilities": ["chat"],
                    "SupportedParameters": ["temperature", "max_tokens"],
                    "Limits": {
                        "context_window": 128000
                    },
                    "Prices": {
                        "input_cost_per_token": 0.000001,
                        "output_cost_per_token": 0.000002,
                        "cache_read_input_token_cost": 0.0000005
                    },
                    "TierPrices": {
                        "peak": {
                            "input_cost_per_token": 0.000002,
                            "output_cost_per_token": 0.000004,
                            "cache_read_input_token_cost": 0.000001
                        }
                    }
                }
            ]
        }
    }
}
```

> 说明：
> - 默认 `Prices`：
>   - `input_cost_per_token = 0.000001` 元/Token → 定点整数 `100`
>   - `output_cost_per_token = 0.000002` 元/Token → 定点整数 `200`
>   - `cache_read_input_token_cost = 0.0000005` 元/Token → 定点整数 `50`
> - `TierPrices.peak`：
>   - `input_cost_per_token = 0.000002` 元/Token → 定点整数 `200`
>   - `output_cost_per_token = 0.000004` 元/Token → 定点整数 `400`
>   - `cache_read_input_token_cost = 0.000001` 元/Token → 定点整数 `100`
> - `peak` 价格为默认价格的两倍，便于断言时快速区分。

与 `cluster_rmb` 结构相同，但 `Tiers` 为空、`TierPrices` 为空，仅保留默认 `Prices`。

## 6. 测试例列表

| 编号 | 名称 | 核心验证点 |
|------|------|------------|
| TC-01 | `peak` tier 非流式按 tier 价扣费 | 命中 `peak` 后，Redis 余额按 `prompt*200 + completion*400` 扣减 |
| TC-02 | 无 `Tiers` 按默认价格扣费 | `cluster_no_table` 无 tier，按默认 `Prices` 扣减 |
| TC-03 | `peak` tier + 缓存命中非流式计费 | 后端返回含 `cache_read_tokens`，按 tier cache 拆分公式扣减 |
| TC-04 | `peak` tier + 缓存命中 SSE 流式计费 | SSE 最终 chunk 含 cache usage，按 tier cache 拆分公式扣减 |

## 7. 公共基础设施改造

本场景需要扩展公共测试框架：

1. **`common/mock_backend.go`**：
   - 新增 `ResponseHeaders` 字段，允许测试为 SSE 响应设置 `Content-Type: text/event-stream`。
   - 当响应包含 `text/event-stream` 时，自动使用 chunked 传输（不设置 `Content-Length`），以兼容 `mod_body_process` 对流式响应的处理。

## 8. 依赖与风险

| 风险点 | 说明 | 缓解措施 |
|--------|------|----------|
| 时间不确定性 | `ActiveTierName` 依赖 `time.Now()` | 将 `peak` 配置为全周全天覆盖 |
| 流式响应被截断 | 若 mock 后端返回 Content-Length，BFE 可能按普通响应处理 | SSE 响应自动使用 chunked |
| RMB 扣减存在异步性 | Redis 扣减在响应发送后执行 | 请求发送后等待并轮询 Redis 余额 |
| ModelTable 价格转换精度 | 浮点到定点整数转换可能与预期有 1 单位误差 | 测试用例使用可整除的价格 |

## 9. 与其他场景的依赖关系

- 依赖 SC01 已验证的 `mod_ai_route` 路由表查找与绑定能力；
- 依赖 SC03 已验证的 RMB 配额扣减基础能力；
- 本场景 focus 在 `mod_ai_token_auth` 的分时段 tier 价格匹配链路。
