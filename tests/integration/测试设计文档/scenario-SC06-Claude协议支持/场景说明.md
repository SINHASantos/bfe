# SC06 Claude 协议支持

## 1. 场景背景与目的

BFE AI 网关在 v0.5 起支持识别并转发 Anthropic Claude Messages API 请求。本场景验证：

- BFE 能根据请求路径/头自动识别 `openai` 与 `anthropic` 协议风格；
- 按协议风格向上游注入正确的认证头（`Authorization: Bearer` 或 `x-api-key`）；
- Anthropic 风格自动补 `anthropic-version: 2023-06-01`；
- `AIConf.ModelProtocols` 用于校验请求协议与集群 provider 支持协议是否匹配，不匹配时直接拒绝；
- 多协议集群可同时支持 OpenAI 与 Anthropic 请求；
- Claude 响应 usage 字段（`input_tokens` / `output_tokens` / `cache_read_input_tokens` / `cache_creation_input_tokens`）被正确解析。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | 启用 `EnableAiGateway`，加载 `mod_ai_route` |
| `mod_ai_route/mod_ai_route.conf` | 指定 `ai_route.data` 路径 |
| `mod_ai_route/ai_route.data` | 定义 3 条 apikey 级路由规则，按 Host 路由到不同 cluster |
| `server_data_conf/host_rule.data` | 声明 `ai_product` 产品线对应的 3 个 Host |
| `server_data_conf/route_rule.data` | 默认路由（本场景不命中） |
| `cluster_conf/cluster_conf.data` | 运行时根据 mock 后端与 `AIConfs` 动态生成 |
| `cluster_conf/gslb.data` | GSLB 权重配置 |
| `cluster_conf/cluster_table.data` | 运行时根据 mock 后端地址动态生成 |

## 4. 测试 Cluster 与 Key 配置

### 4.1 cluster_openai_only

```json
{
    "AIConf": {
        "Type": 0,
        "ModelProtocols": ["openai"],
        "Keys": [
            {"Name": "openai-key", "Key": "sk-openai-key", "Weight": 100}
        ]
    }
}
```

### 4.2 cluster_anthropic_only

```json
{
    "AIConf": {
        "Type": 0,
        "ModelProtocols": ["anthropic"],
        "Keys": [
            {"Name": "anthropic-key", "Key": "sk-anthropic-key", "Weight": 100}
        ]
    }
}
```

### 4.3 cluster_both_protocols

```json
{
    "AIConf": {
        "Type": 0,
        "ModelProtocols": ["openai", "anthropic"],
        "Keys": [
            {"Name": "both-openai-key", "Key": "sk-both-openai-key", "Weight": 50},
            {"Name": "both-anthropic-key", "Key": "sk-both-anthropic-key", "Weight": 50}
        ]
    }
}
```

> 说明：多协议 cluster 中配置了两个 key，分别用于 OpenAI 与 Anthropic 请求验证，避免单 key 被两种请求复用导致断言混淆。

### 4.4 路由表设计

#### apikey_ak_user_a

| 规则名 | 条件 | targets | fallbacks |
|--------|------|---------|-----------|
| user_a-openai | `req_host_in("openai.example.org")` | `cluster_openai_only` | 无 |
| user_a-anthropic | `req_host_in("anthropic.example.org")` | `cluster_anthropic_only` | 无 |
| user_a-both | `req_host_in("both.example.org")` | `cluster_both_protocols` | 无 |

#### ApikeyRouteTableBindings

```json
{
    "ak_user_a": ["apikey_ak_user_a"]
}
```

## 5.1 测试例详细说明

### TC-01 OpenAI 风格转发

**目的**：验证 OpenAI 风格请求被正确路由到仅支持 `openai` 协议的集群，并使用 `Authorization: Bearer` 注入集群 key。

**请求构造**：

| 字段 | 值 |
|------|-----|
| Host | `openai.example.org` |
| Path | `/v1/chat/completions` |
| Header | `Authorization: Bearer ak_user_a` |
| Body | `{"model":"gpt-4"}` |

**预期结果**：

- 响应状态码 200。
- `cluster_openai_only` mock backend 命中 1 次。
- upstream 收到的 `Authorization` 头为 `Bearer sk-openai-key`。
- upstream 未收到 `x-api-key` 头。

### TC-02 Anthropic 风格转发

**目的**：验证 Anthropic 风格请求被正确路由到仅支持 `anthropic` 协议的集群，并使用 `x-api-key` 注入集群 key，同时自动补 `anthropic-version`。

**请求构造**：

| 字段 | 值 |
|------|-----|
| Host | `anthropic.example.org` |
| Path | `/v1/messages` |
| Header | `x-api-key: ak_user_a` |
| Body | `{"model":"claude-3-5-sonnet","messages":[{"role":"user","content":"hi"}]}` |

**预期结果**：

- 响应状态码 200。
- `cluster_anthropic_only` mock backend 命中 1 次。
- upstream 收到的 `x-api-key` 头为 `sk-anthropic-key`。
- upstream 收到的 `anthropic-version` 头为 `2023-06-01`。
- upstream 未收到 `Authorization` 头。

### TC-03 Anthropic 请求命中 OpenAI-only 集群

**目的**：验证请求协议与集群 `ModelProtocols` 不匹配时，BFE 直接拒绝且不访问 upstream。

**请求构造**：

| 字段 | 值 |
|------|-----|
| Host | `openai.example.org` |
| Path | `/v1/messages` |
| Header | `x-api-key: ak_user_a` |
| Body | `{"model":"claude-3-5-sonnet","messages":[{"role":"user","content":"hi"}]}` |

**预期结果**：

- 响应状态码 400。
- 响应体包含 `PROVIDER_PROTOCOL_MISMATCH`。
- `cluster_openai_only` mock backend 命中 0 次。

### TC-04 OpenAI 请求命中 Anthropic-only 集群

**目的**：验证 OpenAI 风格请求命中仅支持 `anthropic` 的集群时同样被拒绝。

**请求构造**：

| 字段 | 值 |
|------|-----|
| Host | `anthropic.example.org` |
| Path | `/v1/chat/completions` |
| Header | `Authorization: Bearer ak_user_a` |
| Body | `{"model":"gpt-4"}` |

**预期结果**：

- 响应状态码 400。
- 响应体包含 `PROVIDER_PROTOCOL_MISMATCH`。
- `cluster_anthropic_only` mock backend 命中 0 次。

### TC-05 多协议集群同时支持两种请求

**目的**：验证 `ModelProtocols` 同时包含 `openai` 与 `anthropic` 的集群能够按请求风格选择正确的 key 与头部。

**请求构造**：向 `both.example.org` 连续发送 2 个请求：

1. OpenAI 风格：`POST /v1/chat/completions`，`Authorization: Bearer ak_user_a`，body `{"model":"gpt-4"}`。
2. Anthropic 风格：`POST /v1/messages`，`x-api-key: ak_user_a`，body `{"model":"claude-3-5-sonnet","messages":...}`。

**预期结果**：

- 两个请求均返回 200。
- `cluster_both_protocols` mock backend 命中 2 次。
- OpenAI 请求 upstream 收到 `Authorization: Bearer sk-both-openai-key`（或对应 Anthropic key 以 Bearer 形式注入，取决于加权随机选中的 key）。
- Anthropic 请求 upstream 收到 `x-api-key: sk-both-anthropic-key` 与 `anthropic-version: 2023-06-01`。

> 说明：由于加权随机选 key，断言策略为“存在符合协议风格的 header 即可”，不强制固定某一把 key。

### TC-06 双头存在时 Authorization 优先

**目的**：验证请求同时携带 `Authorization` 与 `x-api-key` 时，BFE 按 OpenAI 风格处理（`DetectAuthStyle` 优先识别 Authorization）。

**请求构造**：

| 字段 | 值 |
|------|-----|
| Host | `both.example.org` |
| Path | `/v1/chat/completions` |
| Header | `Authorization: Bearer ak_user_a`、`x-api-key: ak_user_a` |
| Body | `{"model":"gpt-4"}` |

**预期结果**：

- 响应状态码 200。
- upstream 收到的 `Authorization` 头携带集群 key（`Bearer sk-both-openai-key` 或 `Bearer sk-both-anthropic-key`）。

### TC-07 显式 anthropic-version 被保留

**目的**：验证客户端显式传递的 `anthropic-version` 不会被 BFE 的默认值覆盖。

**请求构造**：

| 字段 | 值 |
|------|-----|
| Host | `anthropic.example.org` |
| Path | `/v1/messages` |
| Header | `x-api-key: ak_user_a`、`anthropic-version: 2023-06-02` |
| Body | `{"model":"claude-3-5-sonnet","messages":[{"role":"user","content":"hi"}]}` |

**预期结果**：

- 响应状态码 200。
- upstream 收到的 `anthropic-version` 头仍为 `2023-06-02`。

### TC-08 Claude usage 字段解析

**目的**：验证 Claude 响应中的 `input_tokens`、`output_tokens` 及 cache 相关字段可被 BFE 正常解析，不影响响应返回。

**请求构造**：

| 字段 | 值 |
|------|-----|
| Host | `anthropic.example.org` |
| Path | `/v1/messages` |
| Header | `x-api-key: ak_user_a` |
| Body | `{"model":"claude-3-5-sonnet","messages":[{"role":"user","content":"hi"}]}` |

**Mock 后端响应**：

```json
{
  "content": [{"text":"ok"}],
  "usage": {
    "input_tokens": 100,
    "output_tokens": 50,
    "cache_read_input_tokens": 30,
    "cache_creation_input_tokens": 20
  }
}
```

**预期结果**：

- 响应状态码 200。
- `cluster_anthropic_only` mock backend 命中 1 次。
- BFE 不报错、不中断响应。

## 7. 与其他场景的依赖关系

- 依赖 SC01 已验证的 `mod_ai_route` 路由表查找与绑定能力；
- 不依赖 SC02 的 Key 级重试逻辑，本场景每个 cluster 仅配置单 Key（多协议 cluster 配置两个 key 仅用于区分协议）。
