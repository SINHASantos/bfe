# SC08 AI 模型 Fallback 重算

## 1. 场景背景与目的

在 AI 网关转发过程中，BFE 会根据 `mod_ai_route` 的 target/fallback 配置以及 cluster 的 `AIConf` 对请求体中的 `model` 字段进行改写。当主 cluster 失败触发 fallback 时，必须保证 fallback cluster 从原始 `ClientModel` 重新计算目标模型，而不是继承主 cluster 改写后的结果。本场景验证：

- fallback 到新 cluster 时，`targetModel` 从 `aiMeta.ClientModel` 重新计算；
- fallback cluster 应用自身的 `ModelMapping`、`StripPrefix` 等配置，而不是主 cluster 的配置结果；
- `bodyModel` 缓存机制能正确避免重复改写请求体。

## 2. 运行模式

- **单组件模式**：仅启动真实 `bfe` 进程。
- 不涉及 `ai-gateway-api` 与 `conf-agent`。

## 3. 涉及的 BFE 配置文件

| 文件 | 说明 |
|------|------|
| `bfe.conf` | 启用 `EnableAiGateway`，加载 `mod_ai_route` |
| `mod_ai_route/mod_ai_route.conf` | 指定 `ai_route.data` 路径 |
| `mod_ai_route/ai_route.data` | 定义 apikey 级路由规则，包含 target 与 fallback |
| `server_data_conf/host_rule.data` | 声明 `ai_product` 产品线对应的 Host |
| `server_data_conf/route_rule.data` | 默认路由 |
| `server_data_conf/vip_rule.data` | VIP 配置 |
| `cluster_conf/gslb.data` | GSLB 权重配置 |
| `cluster_conf/cluster_table.data` | 运行时根据 mock 后端地址动态生成 |
| `cluster_conf/cluster_conf.data` | 运行时根据 mock 后端动态生成，包含各 cluster 的 `AIConf` |

## 4. 测试 Cluster 与 AIConf 配置

### 4.1 cluster_openrouter（主 cluster）

```json
{
    "AIConf": {
        "Type": 0,
        "MatchPrefix": "openrouter/",
        "StripPrefix": true,
        "ModelMapping": {
            "modelA": "mapped-primary-model"
        },
        "Keys": [
            {"Name": "primary-key", "Key": "sk-primary-key", "Weight": 100}
        ]
    }
}
```

### 4.2 cluster_fallback（fallback cluster，TC-01 无 strip）

TC-01 中 fallback cluster 不配置 `AIConf`，仅透传重新计算后的模型。

### 4.3 cluster_fallback（fallback cluster，TC-02 带 strip）

```json
{
    "AIConf": {
        "Type": 0,
        "MatchPrefix": "clientprefix/",
        "StripPrefix": true
    }
}
```

### 4.4 cluster_default

默认兜底 cluster，本场景不命中。

### 4.5 路由表设计

#### apikey_ak_user_a

| 规则名 | 条件 | targets | fallbacks |
|--------|------|---------|-----------|
| user_a-openrouter | `req_body_json_prefix_in("model", "clientprefix/", false)` | `cluster_openrouter`，Model 覆盖为 `openrouter/modelA` | `cluster_fallback`，Model 为空 |
| user_a-default | `default_t()` | `cluster_default` | 无 |

## 5. 测试例列表

| 编号 | 名称 | 核心验证点 |
|------|------|------------|
| TC-01 | Fallback 从 ClientModel 重新计算 | 主 cluster 失败后，fallback cluster 收到的是原始 client model，而不是主 cluster 的 mapped model |
| TC-02 | Fallback 应用自身 strip 配置 | fallback cluster 从 ClientModel 重新计算后，应用自身的 `StripPrefix` 配置 |

## 5.1 测试例详细说明

### TC-01 Fallback 从 ClientModel 重新计算

**目的**：验证 fallback 时不会继承主 cluster 的 `TargetModel`。

**请求构造**：

| 字段 | 值 |
|------|-----|
| Host | `api.example.org` |
| Path | `/v1/chat/completions` |
| Header | `Authorization: Bearer ak_user_a` |
| Body | `{"model":"clientprefix/mymodel","messages":[{"role":"user","content":"hello"}]}` |

**Cluster 行为**：

- `cluster_openrouter` 返回 503，触发 fallback；
- `cluster_fallback` 返回 200。

**主 cluster 模型计算**：

1. target Model 覆盖：`openrouter/modelA`
2. strip `openrouter/`：`modelA`
3. ModelMapping：`mapped-primary-model`

**fallback cluster 模型计算**：

1. target Model 为空，保持 `ClientModel`：`clientprefix/mymodel`
2. 无 ModelMapping、无 strip

**预期结果**：

- 响应状态码 200。
- `cluster_openrouter` mock backend 命中 1 次，收到的 model 为 `mapped-primary-model`。
- `cluster_fallback` mock backend 命中 1 次，收到的 model 为 `clientprefix/mymodel`。
- `cluster_default` mock backend 命中 0 次。

> 说明：若 fallback 继承主 cluster 的 `TargetModel`，fallback 将收到 `mapped-primary-model`，测试会失败。

### TC-02 Fallback 应用自身 strip 配置

**目的**：验证 fallback cluster 不仅从 `ClientModel` 重算，还会应用自身的 `StripPrefix` 配置。

**请求构造**：

| 字段 | 值 |
|------|-----|
| Host | `api.example.org` |
| Path | `/v1/chat/completions` |
| Header | `Authorization: Bearer ak_user_a` |
| Body | `{"model":"clientprefix/mymodel","messages":[{"role":"user","content":"hello"}]}` |

**Cluster 行为**：

- `cluster_openrouter` 返回 503，触发 fallback；
- `cluster_fallback` 返回 200。

**主 cluster 模型计算**（同 TC-01）：最终为 `mapped-primary-model`。

**fallback cluster 模型计算**：

1. target Model 为空，保持 `ClientModel`：`clientprefix/mymodel`
2. strip `clientprefix/`：`mymodel`

**预期结果**：

- 响应状态码 200。
- `cluster_openrouter` mock backend 命中 1 次，收到的 model 为 `mapped-primary-model`。
- `cluster_fallback` mock backend 命中 1 次，收到的 model 为 `mymodel`。

## 6. 公共基础设施

本场景使用测试框架内置能力：

1. **`common/mock_backend.go`**：记录 upstream 收到的请求 model，供断言使用。
2. **`common/bfe_config_builder.go`**：根据 `AIConfs` 动态生成 `cluster_conf.data`。

## 7. 与其他场景的依赖关系

- 依赖 SC01 已验证的 `mod_ai_route` 路由表查找与 fallback 能力；
- 依赖 SC04 已验证的 ProviderModel 前缀裁剪能力；
- 不依赖 SC02 的 Key 级重试逻辑，本场景每个 cluster 仅配置单 Key。
